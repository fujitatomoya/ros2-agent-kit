# Issue report

You prepare `.ros2-agent-kit/ISSUE_BODY.md`; the human writes the words, and the issue is filed only after they confirm the exact command.

## 1. Where does it belong

1. Identify the package from the symptom (a crash in a header, a CLI verb, a message type).
2. Find its repository from the installed package:

   ```bash
   ros2 pkg xml <package> | grep -i '<url'
   ```

   or from the common mapping in `references/trackers.md`.
3. Questions about usage belong on https://robotics.stackexchange.com/, not in a tracker.
   Say so when the report is really a question.

## 2. Search for duplicates

```bash
gh search issues --repo ros2/<repo> "<two or three key words>" --state all --limit 10
gh search issues --owner ros2 --owner ament "<key words>" --state open --limit 10
```

Show the candidates to the user.
If one matches, the right action is a comment by the human on that issue, not a new one.

## 3. Collect the facts mechanically

Run these and paste the output verbatim; do not paraphrase it:

```bash
uname -a
echo "$ROS_DISTRO"
ros2 doctor --report
```

From the report take the `middleware name` line for the RMW implementation.
Note the client library (`rclcpp`, `rclpy`) from the user's code.
Verbatim command output may be inserted by you; that is the one kind of issue text you write.

## 4. Write the body

Get the form from the repository or the cached organization default (`tools/fetch_templates.py ros2`).
Mirror the form's labels as `### <label>` headings, in the form's order, and put this hint on the first line so the gate knows which form to check against:

```markdown
<!-- ros2-gate: template=bug_report -->
```

Fill in:

- `Generated by Generative AI`: the tool and model, whenever you helped prepare the issue.
- Operating system, ROS version or commit, RMW implementation, client library, and the `ros2 doctor --report` output inside `<details>`.

Leave for the human, each with an HTML comment that prompts them:

- the title (propose one in your summary, clearly marked as a proposal),
- Steps to reproduce,
- Expected behavior,
- Actual behavior.

Check the draft (empty human sections are warnings until the human fills them):

```bash
python3 "${CLAUDE_PLUGIN_ROOT:-.}/gate/ros2-gate" check-issue-body .ros2-agent-kit/ISSUE_BODY.md
```

## 5. Submit after confirmation

Once the human has filled their sections, show them the exact command and ask them to confirm it:

```bash
gh issue create --repo ros2/<repo> --title "<title>" --body-file .ros2-agent-kit/ISSUE_BODY.md --label bug
```

Confirming means the human wrote the title, the reproduction, and the expected and actual behavior, and checked the facts you collected; say so when you ask.
Run the command only after they confirm.
Gate G3 enforces this: in Claude Code it shows the permission prompt for the command, and in a harness that cannot prompt from a hook it blocks the command, in which case the human runs it.

Mention `gh issue create --repo ros2/<repo> --web` as the alternative that opens the form in the browser for pasting.
